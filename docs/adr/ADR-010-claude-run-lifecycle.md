# ADR-010. Жизненный цикл Claude-хода — таймаут бездействия, сироты, рестарт

## Контекст

- Живые Claude-ходы (`#runs`) хранятся в памяти. При рестарте `server.js`
  дочерний `claude.exe` на Windows продолжает работать (сирота) и может
  менять файлы. Вопрос пользователя уже записан в `claude-sessions.json`,
  ответа нет; `#managed` пуст, pending для Claude не ведётся. Чат выглядит
  «мёртвым» без баннера.
- Таймаута по умолчанию нет (`ZAI_CLAUDE_TIMEOUT_MS=0`): жёсткий таймаут
  15 мин от старта убивал легитимные длинные ходы.
- Keepalive раз в 45 с шлёт `session.status busy`. Это обновляет
  stall-часы клиента, поэтому зависший CLI выглядит живым бесконечно.
  Хаб исключает managed-ходы из abort/replay; комментарий hub.js:643
  («the runner kills its own hung turns») по умолчанию не соответствует
  поведению.
- stdin ребёнка не закрывается: CLI, ожидающий ввод, висит (SEC-21).
- Событие `assistant` затирает накопленный текст многошагового ответа
  (COR-13).

## Решение (предлагается)

1. **Таймаут бездействия** вместо таймаута от старта: часы сбрасываются
   на каждую строку stdout. По умолчанию 15 мин тишины
   (`ZAI_CLAUDE_IDLE_MS`, через ADR-006); `ZAI_CLAUDE_TIMEOUT_MS` остаётся
   как жёсткий потолок, по умолчанию выключен.
2. **Keepalive без обмана**: отдельный тип события
   `zai.keepalive {sessionID, lastOutputAt}`. Клиент держит соединение, но
   stall-часы считает от `lastOutputAt`.
3. **PID-файл** `data/claude-runs.json` `{sid: {pid, startedAt}}` с
   атомарной записью (ADR-002). При старте сервера: для каждой записи —
   завершить процесс, если он жив и это `claude.exe`; в историю чата
   дописать ответ «[Прервано рестартом портала]»; удалить запись.
4. **Вопрос без ответа** при старте (последнее сообщение — user, процесса
   нет): та же системная реплика; в UI — кнопка «Отправить снова»
   (переиспользует `retryFailed`).
5. `child.stdin.end()` сразу после spawn (или запись промпта, ADR-004).
6. Текст ответа: накапливать `assistant`-блоки по сообщениям, а не
   заменять (COR-13).

## Последствия

- Плюсы: после рестарта чат честно показывает прерванный ход; сироты не
  меняют файлы после рестарта; зависший CLI виден клиенту и убивается
  сервером.
- Минусы и риски: длинный ход с долгим молчанием (>15 мин без вывода)
  будет прерван — порог проверить на реальных dogfood-задачах на стенде;
  убийство процессов по PID требует проверки имени образа, чтобы не задеть
  чужой процесс с переиспользованным PID.
- Почему не сейчас: меняет поведение длинных ходов, недавно уже
  откатывали таймаут; опирается на ADR-002 (атомарная запись) и ADR-005
  (resync после рестарта), которые идут первыми.
- Тесты: `claude-server.test.js` с fake CLI — тишина > idle → kill и
  «[Прервано по бездействию]»; рестарт сервера с живой записью в PID-файле
  → системная реплика; многошаговый ответ сохраняет все блоки.
