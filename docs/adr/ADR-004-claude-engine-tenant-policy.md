# ADR-004. Политика движка Claude для тенантов и безопасный запуск CLI

## Контекст

- Любой пользователь, включая тенанта, может выбрать модель `anthropic/*`.
  Тогда `ClaudeRunner` запускает `claude.exe` от имени владельца: его
  подписка, его `~/.claude` (permissions `PowerShell`, `Read/Edit/Write(D:/**)`,
  MCP, CLAUDE.md), `cwd` — каталог тенанта без песочницы. На стенде агент
  тенанта выполнил `whoami` и прочитал `D:\Portal\zai\package.json` (SEC-2).
- Дочерний процесс наследует весь `process.env` сервера, включая
  `ZAI_ADMIN_TOKEN` и `CLAUDE_CODE_OAUTH_TOKEN` (SEC-9).
- Промпт передаётся позиционным аргументом: `["-p", prompt, …]`. Текст,
  начинающийся с `-`, CLI разбирает как опцию (`--version`,
  `--permission-mode=…`, `--add-dir=C:\`), что подтверждено локально
  (SEC-11). Длина командной строки Windows ограничена ~32 К символов, а
  тело промпта — 64 МБ (COR-14).
- `modelID` из тела не сверяется с каталогом.

## Решение

1. **Политика ролей.** Поле пользователя `engines: ["opencode"] |
   ["opencode","claude"]`. По умолчанию: admin — оба движка, тенант —
   только `opencode`. Гейт в `POST /session`, `PATCH …/binding` и
   `POST …/prompt`: привязка с `engine=claude` для пользователя без права —
   403 «engine not allowed». `/provider` для такого пользователя не
   содержит группу `anthropic`. Админ включает Claude тенанту явно в
   AccessSection.
2. **Промпт через stdin.** `claude.exe -p --input-format text …`,
   `child.stdin.end(prompt)`. Если версия CLI не поддерживает stdin для
   `-p`, минимум — `--` перед промптом. Это снимает и инъекцию опций, и
   лимит argv.
3. **Минимальное окружение.** `spawn(…, { env })` с явным списком:
   `PATH`, `SystemRoot`, `TEMP`/`TMP`, `USERPROFILE`, `APPDATA`,
   `LOCALAPPDATA`, при необходимости `CLAUDE_CODE_OAUTH_TOKEN`. Все `ZAI_*`
   вычищаются. Мёртвое поле `#token` удаляется или начинает использоваться
   явно.
4. **Валидация модели.** `modelID` допускается только из `MODEL_CATALOG`;
   иначе 400. Каталог становится единственным источником (снимает
   дублирование `DEFAULT_CLAUDE_MODEL` в binding.js/claude.js — первый шаг
   S15).
5. **Тенанту, которому Claude включён**, CLI запускается с ограничениями:
   `--permission-mode default`, `--settings <tenant.json>` с `deny` на
   Bash/PowerShell и Read/Edit вне `cwd`, `--strict-mcp-config`, отдельный
   `CLAUDE_CONFIG_DIR` на тенанта. Точный набор флагов фиксируется после
   проверки на установленной версии CLI на стенде.

## Последствия

- Плюсы: тенант по умолчанию не получает shell владельца через Claude;
  секреты сервиса не попадают агенту; сообщения, начинающиеся с «- пункт»,
  перестают ломать ход; длинные промпты работают.
- Ограничение решения: opencode-агенты тенантов по-прежнему исполняются с
  правами владельца (`bash: allow` в конфиге opencode). Полная изоляция —
  отдельная учётная запись Windows или VM; это инфраструктурное решение
  вне кода портала (см. architecture.md §9.3). До него новые тенанты на
  прод не заводятся.
- Минусы: тенанты с уже существующими Claude-чатами потеряют возможность
  писать в них, пока админ не включит им движок; миграция — однократный
  список таких тенантов в логе при старте.
- Тесты: L3 (`claude-server.test.js`) — 403 для тенанта без права; промпт
  `--version` доходит до fake CLI как текст через stdin; в env ребёнка нет
  `ZAI_*`; неизвестный modelID → 400.
