# ADR-002. Атомарная запись JSON-хранилищ и карантин испорченных файлов

## Контекст

Портал хранит состояние в трёх JSON-файлах в `ZAI_DATA_DIR`:

| Файл | Запись сейчас | При ошибке разбора |
|---|---|---|
| `users.json` | tmp+rename | `initAuth()` создаёт **нового** admin со случайным токеном и перезаписывает файл: все тенанты теряются молча |
| `session-bindings.json` | tmp+rename, ошибки глотаются | старт с пустого |
| `claude-sessions.json` | `writeFileSync` целиком, **без** tmp+rename (claude.js:454–459), 2 раза за ход и на каждый DELETE | старт с пустого; первая запись затирает испорченный файл |

`claude-sessions.json` — единственная копия истории Claude-чатов (≈41 КБ на
2026-11-02, растёт без ограничений, содержит data:URL картинок). Цепочка
«падение процесса посреди записи → рестарт → пустое хранилище → первая
запись» стирает всю историю. Падения процесса реальны (R1 до фикса
`parseCookies`).

## Решение

1. Общий helper `lib/jsonstore.js` (zero-dep):
   - `readJson(path)` → `{data}` | `{missing}` | `{corrupt, error}`;
   - `writeJsonAtomic(path, data)`: запись в `<path>.tmp` с `fsync`, затем
     `renameSync` поверх. На Windows rename поверх существующего файла
     атомарен в пределах тома.
2. При `corrupt`: файл переименовывается в `<path>.corrupt-<ISO-время>`,
   в лог пишется громкая строка `[zai-store] CORRUPT …`, хранилище стартует
   пустым. Испорченный файл не затирается.
3. `users.json`: при `corrupt` — **fail-fast**: процесс завершается с кодом
   1 и понятным сообщением. Пересоздание admin — только при `missing`.
4. `ClaudeRunner.#flush` и `BindingStore.#flush` переходят на
   `writeJsonAtomic`. Ошибка записи логируется (с троттлингом), а не
   глотается.
5. Перспектива (не в 1.6.2): `claude-sessions.json` → файл на сессию
   `data/claude/<sid>.json`. Это снимает перезапись всего файла на каждый
   ход и упрощает пагинацию (S21) и сборку мусора (S18).

## Последствия

- Плюсы: потеря всей истории Claude или всех тенантов из-за одной
  оборванной записи исключена; порча диагностируется по логу и файлу
  `.corrupt-*`.
- Минусы: fail-fast для `users.json` означает, что портал не поднимется при
  ручной опечатке в файле. Это осознанно: лучше упавший сервис с ясной
  ошибкой, чем тихо потерянные тенанты. Watchdog будет перезапускать задачу
  каждые 2 мин — сообщение в логе должно указывать, что делать.
- Тесты (L1): оборванный tmp не портит основной файл; испорченный файл
  уходит в карантин; `users.json` corrupt → exit 1; missing → seed admin.
- Миграция данных не нужна: формат файлов не меняется.
