## Главные отличия v2 (коротко)

1. API весь под `/api/*` с Basic-авторизацией; конверт `{location, data}`; папка — `location[directory]` (deepObject) для instance-маршрутов, тело `POST /api/session` для создания, обычный `?directory=` для списка сессий (api-map, раздел 0).
2. SSE: один глобальный поток `/api/event` вместо per-directory; события с дельтами (`session.text.delta` и т.п.); replay по Last-Event-ID нет (api-map, раздел 2).
3. Ключи провайдеров из auth.json сами не мигрируют — нужен `POST /api/credential`; ходы без него падают с `provider.no-route` (api-map, раздел 10).
4. V1-плагины в v2 не выполняются вовсе — порт vault-cache и slim обязателен; локальный плагин в конфиге регистрируется директорией, поле `plugin` → `plugins` (plugin-map, «Регистрация»; config-map, № 10).
5. Конфиг 1.x нормализуется в памяти (поддерживаемые поля), но только если файл лежит в зоне поиска; наш `ops\opencode\opencode.json` вне зон — v2 его просто не видит (config-map, «Откуда 2.x читает конфиг»).

## Главные риски

1. **Ключи и секреты** (api-map, раздел 10, риск 1): auth.json не мигрирует; ответ `POST /api/credential` эхом возвращает ключ открытым текстом — запрет логирования обязателен. Для стенда/прода нужен скрипт переноса ключей.
2. **Песочница тенантов слабее по умолчанию** (config-map, «Новое в v2», external_directory): в v2 внешние каталоги разрешены без промпта; наши deny-правила Sandbox переносить обязательно, пробу песочницы и jail — гнать до выката (plugin-map, особый пункт 1 — механизм блокировки сохранён, это спасает).
3. **V1-плагины молча не работают** (config-map № 10, plugin-map «Регистрация»): `default_agent: orchestrator` и вся защита тенантов отваливаются, если порт не сделан; локальный плагин-файл в конфиге v2 пропускается с warning.
4. **SSE-переписыватель** (api-map, раздел 2, риск 4): инкрементальные дельты, конверт без `properties`, часть событий без `location`; redactEventForTenant и рендер клиента переписывать; replay нет — кольцевой буфер хаба остаётся критичным.
5. **`system` исчез из тела хода** (api-map, риск 3): FEAT-03.22 (инъекция системного текста в ход) без аналога — кандидат: synthetic-сообщение, не проверено.
6. **Прогрев/здоровье папки** (api-map, риск 2): `/config/providers` нет, dispose ушёл под `/debug` (публичность не гарантирована); нужно заново проверить, отравляется ли instance при прерванной инициализации (сюжет BUG-183).
7. **Модель/variant — состояние сессии, не тела хода** (api-map, раздел 10): перенос variant из lib/glm-variant.js в `POST /session/{id}/model`; гонки при параллельных ходах в одну сессию проверить.
8. **История и пагинация** (api-map, раздел 4, риск 5): плоские сообщения, opaque-курсор; контракт `x-zai-has-more`/`x-zai-next-before` для клиента меняется; tool-часть в истории не проверена.
9. **Вопросы → формы** (api-map, раздел 6, риск 9): модалка портала должна работать с `Form.Info` (типизированные поля); живьём не проверено.
10. **OmO (большой) на 2.x не работает** — slim заменяет его (slim-on-v2), но без `task_revive`/`task_message`/wake-scheduler; проверить, что наши сценарии фоновых субагентов не садятся на баг #1822.

## Вопросы для живого эксперимента с другим конфигом :4099

Текущий :4099 не перезапускать. Нужен **отдельный serve** (другой порт, отдельный data-каталог) с конфигом, приближенным к продовому портала: native-v2 `opencode.json` с `model`, `default_agent: orchestrator` (объявлен явно), `snapshots: false`, MCP playwright/marketplace, предзаполненной credential-таблицей.

1. Слоёный конфиг: `/api/config` с полным файлом — что видно в `info`, применяется ли `snapshots: false` к реверту; видны ли `model`/`default_agent` (api-map, раздел 11; config-map, «Живая проверка»).
2. Прогрев папки: отравляется ли instance при прерванной инициализации в 2.2.6; достаточно ли `/api/mcp` + `/api/model` вместо умершего `/config/providers` (api-map, риск 2).
3. Провайдер из конфиг-файла (не credential): появляются ли модели в `/api/provider`/`/api/model` до первого хода; поведение `/api/model/default` (api-map, раздел 10; config-map, «Живая проверка»).
4. Tool-часть в истории: ход с edit/write — форма tool-сообщения в `GET /message` (api-map, раздел 4).
5. Формы живьём: `form.created/replied/cancelled`, форма ответа `{answer}` (api-map, раздел 6).
6. `decision: "always"` в permission reply — куда сохраняется, работает ли `save` (api-map, раздел 5).
7. `delivery: "queue"` и `?types=` фильтр стрима (api-map, разделы 2–3).
8. Пул MCP: два каталога, `pool: true`, реальные серверы — шаринг подключений, fixed cwd, протокол 2026-07-28 (config-map, «Пул MCP»).
9. Slim на нашем 2.2.6: установка `"plugin": ["oh-my-opencode-slim@3.0.7"]`, health-check `bridges:11`, воспроизведение #1822 на фоновых субагентах, конфликт in-process skills с нашими (slim-on-v2, раздел 5).
10. `OPENCODE_DISABLE_PROJECT_CONFIG`: существует ли и действует в v2 (plugin-map, «Регистрация»).
11. Живые формы `ctx.session.get`/`ctx.session.context` из плагина (обёртка `.data`?) и сохранение `metadata` из prompt-хука на part — для порта vault-cache (plugin-map, «Что не нашлось»).
