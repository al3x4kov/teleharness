# Access-Infra Specification

## Purpose

Инфраструктура доступа: публичный HTTPS-адрес, работа только по HTTPS (http закрыт редиректом 308 с HSTS), автостарт портала при ребуте сервера без входа пользователя, регистронезависимая защита edge-маршрутизации.

## Requirements

### Requirement: Публичный HTTPS-адрес

Система SHALL быть доступна извне по адресу https://zai.home.example.net/zai/: страница отвечает 200, API отвечает 200, SSE-стрим отдаёт данные без буферизации. (трекер: FEAT-08.1)

#### Scenario: Вход снаружи

- **WHEN** портал открывается по внешнему доменному адресу
- **THEN** страница и API отвечают 200, первые байты SSE приходят без задержки

### Requirement: HTTPS-only

Система SHALL отвечать на http-запросы к /zai (порт 80 открыт в firewall правилом Allow) постоянным редиректом 308 на https (единственное исключение — отдача корневого сертификата /zai/ca.pem для устройств) и передавать HSTS на https-ответах; открытых http-эндпоинтов /zai нет. (трекер: FEAT-08.3, BUG-08.5)

#### Scenario: HTTP закрыт

- **WHEN** запрос к /zai идёт по http на порт 80
- **THEN** следует постоянный редирект 308 на https-адрес

#### Scenario: Исключение ca.pem

- **WHEN** устройство скачивает корневой сертификат по http-пути /zai/ca.pem
- **THEN** файл отдаётся без редиректа на https

### Requirement: Автостарт при ребуте

Система SHALL поднимать портал автоматически после перезагрузки сервера без входа пользователя: задачи планировщика с BootTrigger и S4U для edge, портала и opencode, с автоперезапуском и watchdog по портам. (трекер: FEAT-08.4)

#### Scenario: Ребут без логина

- **WHEN** сервер перезагружен и никто не входит в систему
- **THEN** портал самостоятельно поднимается и доступен по внешнему https-адресу

### Requirement: Регистронезависимая edge-маршрутизация

Система SHALL маршрутизировать /zai и блокировать служебные сегменты (zai, zai-qa, .git) без учёта регистра пути: обход регистра не отдаёт файлы данных портала, а легитимные поверхности работают. Регистр нормализуется только при сравнении маршрута и в литеральном префиксе `/zai`. Хвост пути передаётся в портал с исходным регистром, потому что ID сессий регистрозависимы. (трекер: BUG-08.6 (BUG-001), BUG-08.7 (BUG-002))

#### Scenario: Обход регистром

- **WHEN** запрашивается путь /ZAI/data/admin-token.txt или другой вариант регистра
- **THEN** содержимое данных портала не отдаётся, а сам портал при этом работает штатно

#### Scenario: ID сессии со смешанным регистром

- **WHEN** через edge запрашивается /zai/api/session/ses_XXXX/message
- **THEN** портал получает ID в исходном регистре и отвечает 200

### Requirement: Пустые папки тенантов без владельца в GC

Система SHALL показывать в отчёте GET /zai/api/admin/gc подпапки ZAI_TENANT_HOME, которые не принадлежат ни одной учётной записи (`ownerlessTenantDirs`: путь, число файлов, наличие чатов, removable), и при POST удалять только те из них, в которых нет ни одного файла и ни одной папки чата и которые не менялись больше часа. (трекер: BUG-12.19)

#### Scenario: Пустая папка удалённой пробной УЗ

- **GIVEN** в ZAI_TENANT_HOME есть пустая папка probe1 без владельца, старше часа
- **WHEN** администратор запускает POST /zai/api/admin/gc
- **THEN** папка удалена, а папка без владельца с файлами остаётся и видна в отчёте
