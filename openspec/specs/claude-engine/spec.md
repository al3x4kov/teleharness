# claude-engine Specification

## Purpose

Второй движок портала: Claude-модели (провайдер anthropic, подписка Claude) обслуживает claude CLI (lib/claude.js) вместо opencode. Capability описывает каталог моделей, ход как отдельный процесс stream-json с переводом в SSE-контракт портала, историю на стороне портала, продолжение через --resume и остановку.

## Requirements

### Requirement: Маршрутизация Claude-чатов в claude CLI

Система SHALL обслуживать промпты чатов с привязкой к движку claude (провайдер `anthropic`) через claude CLI, а не через opencode. Каждый ход — отдельный процесс `claude -p … --output-format stream-json --model <id>` в директории сессии. Сервер сразу отвечает 204, а ответ приходит событиями hub в SSE-контракте портала. (трекер: FEAT-13.1 — маршрутизация, BUG-11.1)

#### Scenario: Промпт в Claude-чат

- **GIVEN** чат привязан к модели claude-sonnet-4-6
- **WHEN** пользователь отправляет сообщение
- **THEN** сервер отвечает 204, запускает claude CLI с этой моделью в директории сессии, и ответ появляется в чате потоком SSE

### Requirement: Каталог Claude-моделей

Система SHALL добавлять в ответ /zai/api/provider провайдера `anthropic` «Claude (подписка)» с каталогом Claude-моделей портала (все со статусом active, ввод текста и картинок, контекст 200 000). Провайдер помечается подключённым, а дефолтом группы назначается самая свежая Opus (claude-opus-5-5). (трекер: FEAT-13.1, FEAT-11.6)

#### Scenario: Claude в пикере

- **WHEN** клиент запрашивает /zai/api/provider
- **THEN** в ответе есть подключённый провайдер anthropic с каталогом моделей, и claude-opus-5-5 стоит дефолтом группы

### Requirement: История Claude-ходов

Система SHALL хранить ходы claude на стороне портала в data/claude-sessions.json. Сообщение пользователя записывается до запуска процесса, поэтому при сбое запуска вопрос остаётся в истории. Ответ ассистента записывается по завершении хода с моделью и всеми частями хода (шаги, размышления, вызовы инструментов, текст) в порядке их появления. Маршрут истории сессии отдаёт upstream-историю, объединённую с Claude-ходами по времени создания. (трекер: FEAT-13.1, FEAT-13.19)

#### Scenario: История после перезагрузки

- **GIVEN** в чате завершён Claude-ход с размышлениями и вызовами инструментов
- **WHEN** пользователь перезагружает страницу и открывает чат
- **THEN** вопрос и ответ Claude видны в истории в хронологическом порядке, ответ — с размышлениями, карточками инструментов и текстом, как во время хода

### Requirement: Продолжение Claude-сессии

Система SHALL сохранять session_id claude CLI, полученный в результате хода, и передавать его в следующем ходе того же чата флагом `--resume`, чтобы CLI продолжал ту же беседу. (трекер: FEAT-13.12)

#### Scenario: Второй ход

- **GIVEN** первый ход чата вернул session_id claude
- **WHEN** пользователь отправляет следующее сообщение
- **THEN** claude CLI запускается с `--resume <session_id>`

### Requirement: Ход без жёсткого лимита

Система SHALL по умолчанию не ограничивать длительность Claude-хода. Ход идёт, пока CLI не завершится или пользователь его не остановит. Каждые 45 с hub получает событие busy, чтобы долгий ход без вывода не выглядел зависшим. Лимит включается только явно через ZAI_CLAUDE_TIMEOUT_MS: по его истечении ход прерывается, и к тексту добавляется «[Прервано по таймауту]». (трекер: FEAT-13.4)

#### Scenario: Ход дольше 15 минут

- **GIVEN** ZAI_CLAUDE_TIMEOUT_MS не задан
- **WHEN** Claude-ход длится больше 15 минут
- **THEN** сервер не убивает процесс, а клиент получает события busy

### Requirement: Остановка и одиночный ход

Система SHALL держать в Claude-чате один активный ход. Промпт, пришедший во время хода, ставится в серверную очередь и выполняется после текущего хода. «Остановить» завершает процесс CLI, к ответу дописывается «[Прервано]». Идущие ходы видны как busy в /zai/api/status. (трекер: BUG-13.7, FEAT-13.1)

#### Scenario: Остановка Claude-хода

- **WHEN** пользователь нажимает «Остановить» во время Claude-хода
- **THEN** процесс CLI завершается, ход закрывается с пометкой «[Прервано]», и сессия становится idle

#### Scenario: Досылка во время хода

- **GIVEN** в Claude-чате идёт ход
- **WHEN** пользователь отправляет ещё одно сообщение
- **THEN** сервер принимает его в очередь и запускает следующим ходом, без кода 409

### Requirement: Каталог Claude-агентов

Система SHALL держать каталог Claude-агентов в файлах `shared/claude-agents/<id>.md` (поставляется с порталом) и `data/claude-agents/<id>.md` (перекрывает по id, `disabled: true` скрывает). Frontmatter: `name`, `description`, опционально `tools` и `model`; тело — промпт. Каталог перечитывается без рестарта, битый файл пропускается с предупреждением. Агент Workflow входит в каталог, но не выбирается по умолчанию. (трекер: FEAT-13.17)

#### Scenario: Битый файл агента

- **GIVEN** в data/claude-agents лежит файл без frontmatter name
- **WHEN** каталог перечитывается
- **THEN** этот файл пропускается с предупреждением в логе, остальные агенты доступны

### Requirement: Маршрут каталога Claude-агентов

Система SHALL отдавать каталог Claude-агентов по `GET /zai/api/claude/agents` только admin и только полями id, name и description, без промпта и путей. (трекер: FEAT-13.17, FEAT-13.9)

#### Scenario: Агент Workflow в каталоге

- **WHEN** admin запрашивает /zai/api/claude/agents
- **THEN** в ответе есть агент с id workflow, именем «Workflow» и описанием, а промпта агента в ответе нет

#### Scenario: Новый агент файлом

- **GIVEN** портал запущен
- **WHEN** владелец кладёт файл reviewer.md с корректным frontmatter в data/claude-agents
- **THEN** агент появляется в /zai/api/claude/agents без рестарта портала

#### Scenario: Тенант запрашивает каталог

- **WHEN** тенант запрашивает /zai/api/claude/agents
- **THEN** сервер отвечает 403

### Requirement: Агент хода claude CLI

Система SHALL передавать агента привязки Claude-чата в claude CLI флагами `--agents <путь к скомпилированному JSON каталога в ZAI_DATA_DIR> --agent <id>`. В CLI доходит только id из каталога. Поле `model` агента не передаётся: модель хода всегда берётся из привязки (`--model`). Ход без агента запускается с тем же набором аргументов, что и до появления агентов. (трекер: FEAT-13.17)

#### Scenario: Ход с агентом

- **GIVEN** Claude-чат привязан к модели claude-opus-5-5 и агенту workflow
- **WHEN** пользователь отправляет сообщение
- **THEN** claude CLI запускается с `--model claude-opus-5-5 --agents <путь> --agent workflow`, а файл по пути содержит агента workflow без поля model

#### Scenario: Ход без агента

- **GIVEN** Claude-чат без агента
- **WHEN** пользователь отправляет сообщение
- **THEN** в аргументах claude CLI нет `--agents` и `--agent`

### Requirement: Шаги Claude-хода

Система SHALL переводить stream-json claude CLI основной беседы в части сообщения формата opencode и стримить их: `step-start` на шаг модели, `reasoning` со сводкой размышлений (флаг `--settings {"showThinkingSummaries":true}`), `tool` на вызов инструмента (pending → running → completed/error, ввод, вывод, время), `text` на текстовый блок. События подагентов (`parent_tool_use_id`) частей не создают. (трекер: FEAT-13.19)

#### Scenario: Ход с инструментом

- **GIVEN** Claude-чат, модель Claude
- **WHEN** модель размышляет, вызывает Read и Bash и отвечает текстом
- **THEN** клиент получает части reasoning, tool «read», tool «bash» (running → completed с выводом) и text, а лента показывает «Размышления», карточки «Чтение файла» и «Команда» и текст ответа

#### Scenario: Подагент

- **GIVEN** модель вызывает инструмент Task
- **WHEN** подагент работает и возвращает результат
- **THEN** в ленте одна карточка агента (tool «task») с описанием и результатом, а текст и вызовы подагента частями ответа не становятся

### Requirement: Имена инструментов Claude-хода

Система SHALL приводить имена инструментов claude CLI к именам opencode: Bash/PowerShell→bash, Read→read, Edit/MultiEdit→edit, Write→write, Glob→glob, Grep→grep, LS→list, WebFetch→webfetch, WebSearch→websearch, TodoWrite→todowrite, Task/Agent→task; прочие имена (MCP) остаются как есть. (трекер: FEAT-13.19)

#### Scenario: Ярлык карточки

- **WHEN** модель вызывает Grep
- **THEN** часть имеет tool «grep», и карточка подписана «Поиск в файлах»

### Requirement: Завершение Claude-хода с частями

Система SHALL при завершении Claude-хода переводить незакрытые вызовы инструментов в статус error, закрывать незакрытые размышления временем конца и добавлять ошибку Claude, пометку прерывания или «(пустой ответ)» отдельной текстовой частью в конце ответа. (трекер: FEAT-13.19)

#### Scenario: Остановка во время вызова инструмента

- **GIVEN** идёт Claude-ход, вызов инструмента ещё не вернул результат
- **WHEN** пользователь нажимает «Остановить»
- **THEN** карточка вызова получает статус error, а в конце ответа видна пометка «[Прервано]»

### Requirement: Заголовок Claude-чата в начале хода

Система SHALL выставлять автозаголовок Claude-чата сразу после записи первого сообщения пользователя, не дожидаясь конца хода; ручное переименование имеет приоритет. (трекер: BUG-13.20, BUG-142; 108/U017)

#### Scenario: Долгий первый ход

- **GIVEN** новый Claude-чат
- **WHEN** пользователь отправляет первое сообщение и ход длится долго
- **THEN** заголовок появляется в списке чатов, пока ход ещё идёт

### Requirement: Кэш базы знаний в Claude-чатах

Раннер Claude SHALL передавать модели снапшот базы знаний на первом ходе (admin — общий vault, тенант — только своя зона без правил admin), не показывая его в сообщении пользователя. Правила в снапшоте SHALL включать указание: на вопрос о самом пользователе (его вещи, планы, прошлые разговоры) сначала искать в своей базе знаний и только потом отвечать, что сведений нет. (трекер: FEAT-13.11, BUG-01.67)

#### Scenario: Снапшот у Claude

- **WHEN** admin начинает Claude-чат
- **THEN** модель получает снапшот, история содержит чистый текст, снапшот — в `metadata.kbContext`

#### Scenario: Вопрос о пользователе

- **GIVEN** в базе знаний admin есть заметка, где упомянут любимый редактор пользователя
- **WHEN** admin в новом Claude-чате спрашивает «Какой у меня любимый редактор?»
- **THEN** агент ищет в базе знаний и называет редактор без подсказки пользователя

### Requirement: Playwright MCP для admin

При заданном `ZAI_CLAUDE_MCP_CONFIG` с валидным файлом раннер SHALL передавать `--mcp-config` только в admin-ходы; битый или отсутствующий файл игнорируется с записью в лог. (трекер: FEAT-13.10)

#### Scenario: Скриншот через MCP

- **WHEN** admin просит Claude открыть сайт и сделать скриншот
- **THEN** ход использует инструменты `mcp__playwright__*`, PNG появляется в папке чата

### Requirement: Обрезка Claude-сессии при правке и отмене

Раннер Claude SHALL при правке, повторной генерации и отмене хода продолжать разговор с копии транскрипта CLI, обрезанной до выбранного сообщения (`--resume <копия> --fork-session`), и SHALL сохранять до правки копии файлов, которые ход меняет инструментами записи (хук PreToolUse), чтобы ход можно было откатить. (трекер: FEAT-01.57, FEAT-01.58)

#### Scenario: Модель не помнит отменённое

- **GIVEN** Claude-чат, где последний ход отменён или вопрос исправлен
- **WHEN** пользователь спрашивает о содержимом отменённого ответа
- **THEN** модель продолжает с обрезанной истории, отменённого ответа в её контексте нет

### Requirement: Claude только для admin

Система SHALL разрешать движок claude только admin, пока нет OS-изоляции тенантов (ADR-004). Промпт тенанта с Claude-моделью и shell-агенты для тенанта получают 403. (трекер: BUG-12.5, FEAT-13.9)

#### Scenario: Тенант выбирает Claude через API

- **WHEN** тенант отправляет промпт с моделью провайдера anthropic
- **THEN** сервер отвечает 403 и не запускает claude CLI

### Requirement: Режим прав admin-чата

Система SHALL запускать claude CLI в admin-чатах в режиме без интерактивных запросов разрешений (permission-mode и allow-list в конфиге раннера, включая постоянное чтение D:\Portal\zai), чтобы ход не упирался в «разрешение не выдано». Решение записывается в decisions. (трекер: FEAT-13.9)

#### Scenario: Правка файла в admin-чате

- **WHEN** admin просит Claude изменить файл в директории сессии
- **THEN** ход выполняет правку без тупика из-за отсутствия разрешения

### Requirement: Безопасный запуск CLI

Система SHALL передавать промпт claude CLI через stdin в UTF-8, отделяя аргументы `--`. Дочерний процесс получает минимальный env без секретов сервера, stdin закрывается после записи; кириллица доходит без искажений, длина промпта не ограничена лимитом argv. (трекер: BUG-13.2)

#### Scenario: Кириллический промпт

- **WHEN** в Claude-чат отправлено сообщение на русском
- **THEN** CLI получает текст без «????», а ответ относится к заданному вопросу

### Requirement: Живость Claude-хода

Система SHALL показывать в Claude-чате «Работает N мин · последнее действие». Для этого используется отдельный тип keepalive, не похожий на busy-событие. Ход без вывода дольше idle-таймаута прерывается с понятной пометкой. (трекер: BUG-13.3)

#### Scenario: Долгий шаг

- **WHEN** Claude-ход идёт несколько минут
- **THEN** в чате видно время работы и последнее действие

### Requirement: Claude-ходы переживают рестарт

Система SHALL записывать PID идущих Claude-ходов. На старте сервер убивает процессы-сироты, а прерванный ход помечается в истории «[Прервано рестартом]». (трекер: BUG-13.5)

#### Scenario: Рестарт во время хода

- **WHEN** zai-web перезапускается во время Claude-хода
- **THEN** процесс CLI не остаётся сиротой, а ход в истории помечен «[Прервано рестартом]»

### Requirement: Атомарный стор Claude-истории

Система SHALL записывать data/claude-sessions.json атомарно (tmp + rename). Испорченный файл переносится в `.corrupt-<ts>`, а картинки хранятся ссылками, а не base64 (ADR-002). (трекер: BUG-13.6)

#### Scenario: Обрыв записи

- **WHEN** процесс падает во время записи стора
- **THEN** при следующем старте история Claude-чатов читается целиком

### Requirement: Полный многошаговый ответ

Система SHALL накапливать текст ассистента со всех шагов многошагового Claude-хода, не затирая ранние шаги последним. (трекер: BUG-13.8)

#### Scenario: Ответ из нескольких шагов

- **WHEN** Claude отвечает текстом, вызывает инструмент и отвечает снова
- **THEN** в итоговом сообщении сохранены оба фрагмента текста

### Requirement: Playwright MCP для Claude

Система SHALL подключать к claude CLI в admin-чатах тот же Playwright MCP, что у opencode, через `--mcp-config`. (трекер: FEAT-13.10)

#### Scenario: Скриншот страницы

- **WHEN** admin просит Claude открыть страницу и сделать скриншот
- **THEN** ход использует инструменты Playwright и возвращает результат

### Requirement: Единый каталог моделей

Система SHALL определять движок и каталог Claude-моделей в одном модуле shared/engine.js, общем для сервера и клиента. Дефолт каталога — самая свежая Opus, подтверждённая живым прогоном; мёртвый код удаляется. (трекер: FEAT-11.10, TASK-13.13)

#### Scenario: Добавление модели

- **WHEN** в каталог добавляется новая Claude-модель
- **THEN** правка делается в одном месте, и её видят и сервер, и пикер клиента

### Requirement: Объём хранимых Claude-ходов

Система SHALL хранить вывод инструмента Claude-хода не длиннее 16 000 символов, строковые поля ввода инструмента — не длиннее 4 000, а картинки из результатов инструментов не хранить. Картинки из промпта сохраняются в .zai-uploads сессии и передаются CLI текстовой ссылкой. (трекер: FEAT-13.19)

#### Scenario: Длинный вывод инструмента

- **GIVEN** инструмент Claude-хода вернул вывод длиннее 16 000 символов и картинку
- **WHEN** ход сохранён в историю
- **THEN** вывод в истории обрезан до 16 000 символов, картинки из результата в истории нет

#### Scenario: Картинка в промпте

- **WHEN** пользователь отправляет в Claude-чат сообщение с картинкой
- **THEN** картинка лежит в .zai-uploads папки чата, а CLI получает текстовую ссылку на неё

### Requirement: Неожиданное завершение Claude-хода

Система SHALL помечать Claude-ход как прерванный, если процесс claude CLI завершился без итоговой строки `result` и портал его не останавливал. В ответе остаётся сделанная часть, к ней добавляется видимая пометка с кодом или сигналом выхода и подсказкой «Продолжай». У сообщения `zai.interrupted = "crash"`, поэтому интерфейс предлагает «Продолжить». В лог сервера пишется код выхода и хвост stderr без текста промпта. (трекер: BUG-13.24)

#### Scenario: Процесс claude умер посреди хода

- **GIVEN** Claude-ход, процесс которого уже вывел часть ответа
- **WHEN** процесс завершается без строки `result` (код 134, сигнал или код 0), а портал его не останавливал
- **THEN** ответ закрыт, сделанный текст сохранён, добавлена пометка «[Прервано: процесс Claude завершился неожиданно (код N)…]», `zai.interrupted = "crash"`, в логе сервера строка с кодом и хвостом stderr

#### Scenario: Обычные завершения не помечаются

- **GIVEN** ход, завершившийся строкой `result` (успех или `is_error`), либо остановленный кнопкой «Стоп»
- **WHEN** процесс закрывается
- **THEN** пометки «завершился неожиданно» нет; у «Стоп» остаётся «[Прервано]» и `zai.interrupted = "user"`

#### Scenario: Продолжение после обрыва

- **GIVEN** ход, помеченный `crash`
- **WHEN** пользователь пишет «Продолжай»
- **THEN** следующий ход продолжает ту же claude-сессию и отвечает без пометки

### Requirement: Ход Claude закрывается по готовому ответу

Ход Claude-чата SHALL закрываться по событию `result` CLI, даже если процесс CLI продолжает жить, ожидая фоновые задачи агента. Следующее сообщение пользователя SHALL стартовать без очереди: портал останавливает такой процесс и возобновляет сессию CLI. Раунд, который процесс начинает сам после ответа, SHALL показываться отдельным ответом на тот же вопрос. Пустой успешный раунд без текста и инструментов SHALL NOT считаться ответом. (трекер: BUG-184 / BUG-13.25)

#### Scenario: Фоновая задача после ответа

- **GIVEN** агент запустил Bash с run_in_background (sleep 240) и ответил «ГОТОВО»
- **WHEN** CLI прислал `result`, а процесс ждёт задачу
- **THEN** ход закрыт, чат не занят, кнопки «Стоп» нет

#### Scenario: Сообщение после такого ответа

- **GIVEN** ответ закрыт, процесс CLI ждёт фоновую задачу
- **WHEN** пользователь отправляет новое сообщение
- **THEN** оно не встаёт в очередь, процесс останавливается, новый ход отвечает по существу без «(пустой ответ)» и пометок «прервано»

#### Scenario: Уведомление о завершении задачи

- **GIVEN** короткая фоновая задача закончилась раньше нового сообщения
- **WHEN** CLI отвечает на уведомление о ней
- **THEN** в чате появляется ещё один ответ после первого
