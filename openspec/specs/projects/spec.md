# Projects Specification

## Purpose

Раздел «Проекты» с логикой Claude: карточки проектов группируют чаты по директориям сервера, внутри проекта создаются чаты, добавленные вручную проекты можно удалить из списка.

## Requirements

### Requirement: Карточки проектов по директориям

Система SHALL показывать во вкладке «Проекты» карточки, группирующие чаты по директориям: имя проекта, путь и число чатов; переход по карточке открывает экран проекта. (трекер: FEAT-02.2)

#### Scenario: Список проектов

- **WHEN** пользователь открывает вкладку «Проекты»
- **THEN** отображаются карточки по директориям с числом чатов, без обрезки и наложений на мобильной ширине

### Requirement: Создание проекта

Система SHALL позволять добавлять проекты кнопкой «Добавить проект»: принимается только абсолютный путь папки (`X:\…` или UNC `\\host\share`) без `..` и вне системных каталогов Windows; добавленный проект сохраняется между перезагрузками, а физическую папку бэкенд создаёт при первом созданном в нём чате. Сервер отклоняет создание чата с неабсолютной директорией. (трекер: FEAT-02.3, BUG-02.4 (BUG-013))

#### Scenario: Новый проект

- **WHEN** пользователь нажимает «Добавить проект» и задаёт абсолютный путь
- **THEN** карточка проекта появляется в списке, переживает перезагрузку, и первый чат в нём создаётся без ошибок папки

#### Scenario: Относительный путь

- **WHEN** пользователь вводит `relative\folder` или `..\x`
- **THEN** модалка показывает ошибку, проект не добавляется

#### Scenario: Неабсолютная директория в API

- **WHEN** клиент вызывает POST /zai/api/session?directory=relative\folder
- **THEN** сервер отвечает 400 и не создаёт ни папку, ни сессию

### Requirement: Чат внутри проекта

Система SHALL создавать чаты в контексте проекта: экран проекта даёт «Новый чат», сессия создаётся с директорией проекта и принадлежит ему. (трекер: FEAT-02.1)

#### Scenario: Новый чат в проекте

- **WHEN** на экране проекта нажата «Новый чат»
- **THEN** создаётся сессия с директорией проекта, и она видна среди чатов этого проекта

### Requirement: Удаление добавленного

Система SHALL позволять удалять добавленные вручную проекты из списка и удалять чаты действием из списка: удалённое исчезает из списка и не возвращается; удаление чата также забывает его привязку движка и историю Claude-ходов. (трекер: FEAT-02.3; docs/architecture.md §4.1)

#### Scenario: Удаление проекта

- **WHEN** пользователь удаляет добавленный вручную проект
- **THEN** его карточка исчезает из списка и не возвращается после перезагрузки

#### Scenario: Удаление чата

- **WHEN** пользователь удаляет чат действием из списка
- **THEN** сессия исчезает из списка чатов

### Requirement: Каталог чата без проекта

Система SHALL создавать чат без указанного проекта в отдельном каталоге по умолчанию пользователя, а не в System32 или HOME. Пустой ответ upstream при создании считается ошибкой. (трекер: BUG-02.5)

#### Scenario: Новый чат с главной

- **WHEN** пользователь создаёт чат с главной без выбора проекта
- **THEN** директория сессии — каталог по умолчанию портала, а не C:\WINDOWS\system32

### Requirement: Навигация и действия в проекте

Система SHALL возвращать «Назад» из чата туда, откуда он открыт (экран проекта или список чатов), и давать у строк чатов на экране проекта те же действия, что на главной. (трекер: BUG-02.6)

#### Scenario: Назад в проект

- **GIVEN** чат открыт с экрана проекта
- **WHEN** пользователь нажимает «Назад»
- **THEN** открывается экран этого проекта
