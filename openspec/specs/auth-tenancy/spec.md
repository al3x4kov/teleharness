# Auth-Tenancy Specification

## Purpose

Вход на портал по длинному токену без логина и пароля, запоминание устройства cookie на год, пользователи с изолированными зонами чатов и своими tenant-корнями Obsidian, bootstrap-токен администратора.

## Requirements

### Requirement: Экран входа

Система SHALL принимать токен на центрированном экране входа с анимированным знаком zai и фоновым матричным дождём в цветовой гамме темы (при reduced-motion — статичное поле); поле ввода в фокусе автоматически. (трекер: FEAT-04.1, FEAT-04.2)

#### Scenario: Ввод токена

- **WHEN** открыта страница входа
- **THEN** поле токена в центре экрана с анимированным знаком, ввод и отправка работают поверх анимации

### Requirement: Вход и запоминание устройства

Система SHALL входить по валидному токену (POST /zai/api/auth/login), выдавая HttpOnly-cookie с SameSite=Lax, Path=/ и сроком на год (Secure при https), и помнить вход между визитами; невалидный токен — ошибка без входа; POST /zai/api/auth/logout стирает cookie; любой /zai/api/* без валидной cookie отвечает 401. (трекер: FEAT-04.3)

#### Scenario: Успешный вход

- **WHEN** введён валидный токен
- **THEN** устанавливается cookie на год и открывается портал

#### Scenario: Запоминание

- **WHEN** пользователь возвращается на портал в течение срока cookie
- **THEN** вход сохранён, экран ввода токена не показывается

#### Scenario: Без авторизации

- **WHEN** запрос к /zai/api/session приходит без cookie
- **THEN** сервер отвечает 401

### Requirement: Пользователи и скоупы

Система SHALL позволять admin создавать пользователей с генерацией длинного токена: у каждого пользователя своя зона чатов (directories) и свой корень файлов в Obsidian (extraRoots); plaintext-токен показывается ровно один раз, сервер хранит только SHA-256. (трекер: FEAT-04.3)

#### Scenario: Новый пользователь

- **WHEN** admin создаёт пользователя
- **THEN** выдаётся длинный токен ровно один раз, и пользователю назначаются своя зона чатов и tenant-корень Obsidian

### Requirement: Bootstrap admin-токен

Система SHALL при инициализации без данных пользователей генерировать bootstrap-токен администратора в data/admin-token.txt и сообщать его в логе первого старта; admin работает как неограниченный «мир до тенантов». (трекер: FEAT-04.3)

#### Scenario: Первый старт

- **WHEN** сервер стартует без данных пользователей
- **THEN** создаётся bootstrap-токен, вход по нему даёт неограниченные права

### Requirement: Имя cookie инстанса

Система SHALL брать имя cookie авторизации из ZAI_COOKIE_NAME (по умолчанию `zai_t`). Экземпляры портала на одном хосте с разными портами (прод :4170, стенд :4172 с `zai_t_stage`) получают раздельные cookie, и вход в один экземпляр не разлогинивает другой. (трекер: BUG-08.9 (BUG-006))

#### Scenario: Стенд и прод в одном браузере

- **GIVEN** пользователь вошёл на прод 127.0.0.1:4170
- **WHEN** он входит на стенд 127.0.0.1:4172, запущенный с ZAI_COOKIE_NAME=zai_t_stage
- **THEN** обе cookie сосуществуют, и прод продолжает работать без 401

### Requirement: Изолированное выполнение команд тенанта

Система SHALL выполнять команды агента тенанта (инструмент `bash`) только внутри Windows AppContainer этого тенанта: запись разрешена лишь в папку тенанта, код портала, системные файлы Windows, секреты портала, файлы владельца и папки других тенантов недоступны, сетевые обращения к 127.0.0.1 невозможны. Команда передаётся запускателю в base64; при отсутствии запускателя shell тенанту запрещён. Тенанту доступен Python с библиотеками для документов и данных. (трекер: FEAT-04.9)

#### Scenario: Таблица Excel от пользователя

- **GIVEN** тенант приложил .xlsx
- **WHEN** он просит найти в таблице нужные данные
- **THEN** агент читает файл через Python в песочнице и отвечает по содержимому

#### Scenario: Попытка изменить портал

- **WHEN** команда тенанта пытается записать в D:\Portal\zai или C:\Windows, прочитать data/users.json или обратиться к 127.0.0.1:4096
- **THEN** операция отклоняется системой, файлы не меняются

### Requirement: Скиллы документов и marketplace для тенантов

Агенту тенанта SHALL быть доступны скиллы `zai-xlsx`, `zai-docx`, `zai-pptx`, `zai-pdf`, `zai-images`, `zai-html` (рецепты выполняются только в песочнице тенанта) и инструменты MCP marketplace; прочие скиллы тенанту SHALL быть недоступны. (трекер: FEAT-04.10)

#### Scenario: Презентация по просьбе пользователя

- **WHEN** тенант просит сделать презентацию из 4 слайдов
- **THEN** агент загружает скилл zai-pptx и создаёт .pptx в папке тенанта

#### Scenario: Админский скилл

- **WHEN** агент тенанта пытается загрузить скилл не из набора zai-*
- **THEN** плагин отказывает

### Requirement: Набор тенанта в Claude-чатах

Claude-чат тенанта SHALL иметь возможности opencode-агента тенанта: Bash — только в AppContainer тенанта через хук PreToolUse, скиллы zai-* и MCP marketplace доступны, compare_browser_snapshot недоступен. WebFetch SHALL работать только через одобрение хуком для публичных http(s)-адресов; loopback, LAN, link-local и не-http SHALL отклоняться. Субагенты (Task) SHALL быть доступны, их Bash и WebFetch проходят те же хуки; при сбое хука они SHALL отклоняться. (трекер: FEAT-04.11, FEAT-04.12)

#### Scenario: Python в песочнице из Claude-чата

- **GIVEN** тенант с разрешённым движком Claude в чате своей папки
- **WHEN** модель вызывает Bash с командой python
- **THEN** команда выполняется через zai-jail в контейнере тенанта, чтение секретов портала и запись в его код отклоняются

#### Scenario: Хук недоступен

- **GIVEN** файл хука отсутствует или падает
- **WHEN** модель вызывает Bash
- **THEN** вызов не одобрен и отклонён, команда на хосте не выполняется

#### Scenario: WebFetch на внутренний адрес

- **GIVEN** Claude-чат тенанта
- **WHEN** модель вызывает WebFetch на http://127.0.0.1:4096/session или http://192.168.1.1/
- **THEN** хук отклоняет вызов; публичная страница https читается

### Requirement: Только основные агенты тенанта
Список агентов тенанта SHALL NOT содержать субагентов (mode subagent); промпт в чат, привязанный к недоступному тенанту агенту, SHALL выполняться на агенте тенанта по умолчанию.

#### Scenario: Старый чат на субагенте
- GIVEN чат тенанта, привязанный к multimodal-looker
- WHEN тенант отправляет сообщение
- THEN ход выполняется на агенте Sandbox, а не отклоняется 403

### Requirement: Лимит частоты запросов тенанта
Портал SHALL считать в поминутном лимите тенанта (`ZAI_TENANT_RATE_PER_MIN`) только мутирующие запросы; GET и HEAD SHALL NOT расходовать лимит. Admin лимитом не ограничивается.

#### Scenario: Чтение сверх лимита
- **GIVEN** тенант и лимит 5 запросов в минуту
- **WHEN** тенант делает 12 GET-запросов за минуту
- **THEN** все ответы 200

#### Scenario: Мутации сверх лимита
- **GIVEN** тенант и лимит 5 запросов в минуту
- **WHEN** тенант делает 6-й POST за минуту
- **THEN** ответ 429

### Requirement: Модели тенанта только из его каталога
Портал SHALL отказывать тенанту (403 «model not allowed») в привязке чата к модели, которой нет в его `GET /provider` (подключённые провайдеры; Claude — только при разрешённом движке): при создании чата, в PATCH binding и в промпте, создающем привязку. При недоступном каталоге проверка пропускается. Admin не ограничивается.

#### Scenario: Чужая модель при создании чата
- **GIVEN** тенант, в каталоге которого только zai-coding-plan
- **WHEN** тенант создаёт чат с моделью openai/gpt-5
- **THEN** ответ 403 и чат не создаётся

#### Scenario: Первый промпт с чужой моделью
- **GIVEN** непривязанный чат тенанта
- **WHEN** промпт несёт модель вне каталога
- **THEN** ответ 403 и в upstream ничего не уходит

### Requirement: Служебные маршруты тенанта

Система SHALL закрывать для тенанта глобальные каталоги владельца: /host — только admin; /mcp тенанту отдаёт только серверы из белого списка тенанта и только их статус (без текста ошибок); /agent без prompt-полей; /provider отфильтрован по роли. При выключении учётки её SSE-потоки закрываются, а у тенанта действуют квоты. (трекер: BUG-12.10, FEAT-03.21)

#### Scenario: Тенант запрашивает /host

- **WHEN** тенант вызывает /zai/api/host
- **THEN** сервер отвечает 403

#### Scenario: Тенант запрашивает /mcp

- **GIVEN** upstream сообщает playwright с ошибкой и marketplace
- **WHEN** тенант вызывает /zai/api/mcp
- **THEN** ответ содержит marketplace только со статусом и не содержит playwright и текста ошибки

#### Scenario: Учётка выключена

- **WHEN** admin выключает учётку с открытым чатом
- **THEN** её поток событий закрывается, а следующий запрос получает 401

### Requirement: Изоляция vault-cache тенанта

Система SHALL ограничивать инъекцию и запись кэша Obsidian для тенанта его tenant-корнем: чужие и владельческие заметки в контекст тенанта не попадают. (трекер: FEAT-12.15)

#### Scenario: Кэш тенанта

- **WHEN** тенант отправляет сообщение
- **THEN** внедрённый снапшот содержит только заметки из его tenant-корня

### Requirement: Контекст только своей сессии

Система SHALL не подмешивать в ход контекст другой сессии: ни через кэш, ни через гонку открытия, ни через resume. (трекер: BUG-12.14)

#### Scenario: Два чата параллельно

- **WHEN** в двух чатах одновременно идут ходы
- **THEN** ни один ответ не содержит контекста другого чата

### Requirement: Изоляция данных тенантов

Система SHALL изолировать пользователей серверными HTTP-проверками: тенант получает только свои сессии, проекты, статусы, диалоги и SSE-события, а файлы и загрузки — только в своей зоне; директорию сессии для PATCH/DELETE и промптов сервер берёт из своего индекса, а не из запроса; ответ на диалог требует директорию из зоны тенанта; создание чата вне зоны — 403; /zai/api/admin/* и /zai/api/usage требуют роль admin. (трекер: FEAT-04.3, FEAT-04.4)

#### Scenario: Чужие данные недоступны

- **WHEN** тенант запрашивает список чатов, файлов или поток событий
- **THEN** сервер возвращает только объекты его скоупа, чужие объекты отсутствуют

#### Scenario: Admin-API защищён

- **WHEN** не-admin обращается к управлению пользователями
- **THEN** сервер отказывает в доступе

#### Scenario: Чат вне зоны

- **WHEN** тенант создаёт чат с директорией вне своей зоны
- **THEN** сервер отвечает 403 и не создаёт сессию

### Requirement: Агенты тенанта без shell и делегирования

Система SHALL предлагать тенанту и принимать в его чатах только агентов, которым запрещены shell (`bash`), делегирование (`task`) и доступ вне папки (`external_directory`); разрешение `external_directory` только под корнем Obsidian-зон тенантов (`ZAI_TENANT_VAULT`) агента из песочницы не выводит — каждого тенанта в его зоне держит серверная песочница плагина. Admin-чаты этим ограничением не затрагиваются. (трекер: BUG-12.5, BUG-12.20, BUG-12.24)

#### Scenario: Делегирующий агент недоступен тенанту

- **GIVEN** агент без shell, но с разрешённым `task` (Prometheus)
- **WHEN** тенант запрашивает список агентов или привязывает чат к этому агенту
- **THEN** агента нет в списке, привязка получает 403, а чат тенанта по умолчанию идёт на агента-песочницу

#### Scenario: Тенант работает с заметками своей зоны

- **GIVEN** агент Sandbox с `external_directory` deny и allow только `<ZAI_TENANT_VAULT>\*`
- **WHEN** тенант просит прочитать и создать заметку в своей зоне, затем прочитать файл чужой зоны или D:\Obsidian\agents
- **THEN** Sandbox остаётся в списке агентов тенанта, своя заметка читается и создаётся, чужие пути отклоняются «Доступ запрещён»

### Requirement: Серверная песочница инструментов тенанта

Система SHALL плагином opencode на сервере отклонять в tenant-сессии и её субагентах: инструменты вне разрешённого списка, пути вне папки сессии и своей Obsidian-зоны (с учётом junction), запись конфигурации агента (`.opencode`, `.omo`, `.claude`, `opencode.json`) и webfetch на локальные адреса; при неизвестной зоне сессии инструмент не выполняется. Admin-чаты не затрагиваются. (трекер: BUG-12.5, BUG-12.20)

#### Scenario: Инструмент вне песочницы отклонён сервером

- **GIVEN** tenant-сессия или её субагент
- **WHEN** модель вызывает bash, читает файл вне папки (в том числе через `..` или junction), пишет `.opencode/plugin/*` или делает webfetch на 127.0.0.1 или имя, разрешающееся в локальный адрес
- **THEN** плагин отклоняет вызов до выполнения и пишет строку `sandbox blocked` в лог

#### Scenario: Своя папка и admin работают

- **WHEN** тенант создаёт и читает файл в своей папке, а admin в своём чате выполняет shell-команду
- **THEN** обе операции выполняются

### Requirement: Просмотр документов тенанта (zai-render)

Тенант в обоих движках SHALL получать картинки страниц и точный PDF своего документа командой `zai-render <файл>`. Рендер SHALL принимать только файлы внутри папки пользователя и SHALL работать по очищенной копии, недоступной контейнерам тенантов. (трекер: FEAT-04.12)

#### Scenario: Презентация видна модели

- **GIVEN** тенант собрал «deck.pptx» в своей папке
- **WHEN** модель выполняет `zai-render deck.pptx`
- **THEN** в `_preview/deck/` появляются page-01.png … и deck.pdf, команда печатает их список

#### Scenario: Файл вне папки

- **GIVEN** аргумент `..\owner\secret.txt` или абсолютный путь вне папки пользователя
- **WHEN** выполняется zai-render
- **THEN** отказ с кодом 2, рендер не запускается

### Requirement: Рендер не выходит за папку пользователя

Документ или страница при рендере SHALL NOT подтягивать в картинку файлы вне папки пользователя и SHALL NOT обращаться к loopback, LAN или интернету. (трекер: FEAT-04.12)

#### Scenario: Документ-ловушка

- **GIVEN** docx с полем INCLUDETEXT на файл владельца, pptx со связанной картинкой на 127.0.0.1, html с iframe file:// и fetch на 127.0.0.1
- **WHEN** их рендерит zai-render
- **THEN** в PDF нет текста чужого файла и на loopback не приходит ни одного запроса

### Requirement: Пакеты Python тенанта

`pip install <пакет>` в песочнице тенанта SHALL ставить пакет в `<папка пользователя>\.pylibs`, и следующие команды тенанта SHALL импортировать его. Временные папки Python в контейнере SHALL быть доступны процессу на запись. (трекер: FEAT-04.12)

#### Scenario: Установка пакета

- **GIVEN** тенант в своей папке
- **WHEN** выполняет `python -m pip install qrcode`, затем `python -c "import qrcode"`
- **THEN** установка успешна, импорт работает, файлы пакета лежат в `.pylibs` его папки

### Requirement: Рабочая папка в начале команды тенанта

Команда тенанта вида `cd [/d] <папка> && <остаток>` SHALL выполняться в песочнице с рабочей папкой `<папка>`, если она внутри папки пользователя; иначе SHALL быть отклонена. (трекер: FEAT-04.12)

#### Scenario: cd в свою папку

- **GIVEN** Claude-чат тенанта Carol
- **WHEN** модель выполняет `cd /d C:\Users\USER\.zai-tenants\Carol && python -I a.py`
- **THEN** исполняется `python -I a.py` с этой рабочей папкой, без «Access is denied»

### Requirement: Защита тенантов на opencode 2.x

При работе портала на opencode 2.x система SHALL держать серверную песочницу тенантов не слабее, чем на 1.x: запреты плагина 1.x — явными правилами v2, включая deny `external_directory` (кроме зон тенантов); при неизвестной зоне сессии инструмент SHALL NOT выполняться. Логика песочницы SHALL быть общим чистым модулем с одними и теми же юнит-тестами для v1 и v2. (трекер: FEAT-16.3, крит. 2)

#### Scenario: Внешний каталог в v2

- **GIVEN** портал на opencode 2.x, тенант в своей зоне (в v2 доступ к внешним каталогам разрешён по умолчанию)
- **WHEN** модель тенанта читает файл вне его зоны, в том числе внешний каталог, который v2 разрешает без промпта
- **THEN** плагин отклоняет вызов до выполнения с причиной «Доступ запрещён», в логе строка `sandbox blocked`

#### Scenario: Те же классы запретов, что на 1.x

- **GIVEN** портал на opencode 2.x, тенант в своей зоне
- **WHEN** модель тенанта вызывает инструмент вне разрешённого списка, читает путь вне зоны (через `..` или junction), пишет в конфигурацию агента, делает webfetch на локальный адрес или пишет изолированную CJK-вставку
- **THEN** каждый вызов отклонён до выполнения, как на 1.x

#### Scenario: Пробы песочницы и jail на 2.x

- **GIVEN** портал на opencode 2.x и перенесённый плагин
- **WHEN** прогоняются пробы песочницы и проба jail тенантов
- **THEN** все пробы зелёные — защита не слабее, чем на 1.x

#### Scenario: Неизвестная зона

- **GIVEN** сессия, зона которой не определена
- **WHEN** модель вызывает любой инструмент
- **THEN** вызов отклонён до выполнения (fail-closed)

### Requirement: Рабочая папка чата тенанта

Новый чат тенанта SHALL получать рабочую подпапку `<папка тенанта>\chats\<id сессии без ses_>` с доступом к вложениям тенанта через `.zai-uploads`. Команды, относительные пути и создаваемые файлы чата SHALL по умолчанию попадать в неё, в обоих движках. Папка сессии opencode SHALL оставаться корнем тенанта. Чаты, созданные до этой схемы, SHALL работать в корне, как раньше. (трекер: FEAT-04.12)

#### Scenario: Два чата пишут файл с одним именем

- **GIVEN** у тенанта два новых чата
- **WHEN** в каждом модель создаёт `deck.pptx` без пути
- **THEN** файлы лежат в `chats\<id1>\deck.pptx` и `chats\<id2>\deck.pptx` и не затирают друг друга, у каждого ответа своя карточка

#### Scenario: Вложение в чате с подпапкой

- **GIVEN** тенант приложил файл, сообщение ссылается на `.zai-uploads/<имя>`
- **WHEN** модель читает его командой или инструментом из рабочей папки чата
- **THEN** файл читается

#### Scenario: Старый чат

- **GIVEN** чат тенанта, созданный до схемы (подпапки нет)
- **WHEN** модель выполняет команду без пути
- **THEN** команда выполняется в корне папки тенанта, как раньше

### Requirement: Гейт плагина песочницы для тенантов

При `ZAI_OC_API=v2` портал SHALL пускать ход тенанта только после подтверждения плагина песочницы (`GET /api/plugin` называет `zai-tenant-v2` со статусом `active`); без подтверждения (ошибка сети, не-2xx, нет id) ход SHALL отклоняться 403 до побочных эффектов ветки prompt. Админ SHALL NOT зависеть от гейта; история и привязка тенанта SHALL NOT блокироваться. Опрос SHALL кэшироваться: подтверждение `ZAI_PLUGIN_GATE_TTL_MS`, отказ `ZAI_PLUGIN_GATE_TTL_NEG_MS`. (трекер: FEAT-16.3, крит. 2)

#### Scenario: Плагин не подтверждён

- **GIVEN** портал на opencode 2.x, `GET /api/plugin` отвечает 404 (плагин не загрузился, serve работает без песочницы)
- **WHEN** тенант отправляет ход
- **THEN** портал отвечает 403 «sandbox plugin not confirmed…», upstream prompt молчит; ход админа в тот же момент уходит upstream

#### Scenario: Плагин в списке, но не active

- **GIVEN** `GET /api/plugin` называет `zai-tenant-v2` со статусом не `active`
- **WHEN** тенант отправляет ход
- **THEN** портал отвечает 403, ход в serve не уходит

#### Scenario: Плагин подтверждён

- **GIVEN** `GET /api/plugin` называет `zai-tenant-v2` со статусом `active`
- **WHEN** тенант отправляет ход
- **THEN** ход уходит upstream и выполняется в песочнице

#### Scenario: Гейт не трогает чтение

- **GIVEN** гейт закрыт (плагин не подтверждён)
- **WHEN** тенант читает историю чата или меняет привязку модели
- **THEN** запросы отвечают как обычно, 403 только на ходы

### Requirement: Чистка просроченных сессий входа
Сервер SHALL периодически удалять сессии входа старше срока жизни куки и SHALL хранить время последнего обращения каждой сессии.

#### Scenario: Просроченная сессия
- **GIVEN** в хранилище есть сессия старше срока жизни куки и живая сессия
- **WHEN** проходит периодическая чистка
- **THEN** просроченная сессия удалена, живая осталась и продолжает авторизовать запросы

### Requirement: Ограничение перебора на входе
Сервер SHALL отвечать 429 на вход с адреса, превысившего 10 неудачных попыток за минуту, 413 — на тело больше лимита и 400 — на тело, не являющееся JSON.

#### Scenario: Перебор токена
- **GIVEN** с одного адреса за минуту пришло 10 запросов входа с неверным токеном
- **WHEN** приходит одиннадцатый
- **THEN** ответ 429, проверка токена не выполняется

### Requirement: Срок приёма старой куки
Сервер SHALL принимать старую куку с сырым токеном только до даты `ZAI_LEGACY_COOKIE_UNTIL`; после этой даты запрос с такой кукой считается неавторизованным.

#### Scenario: После даты
- **GIVEN** текущая дата позже `ZAI_LEGACY_COOKIE_UNTIL`
- **WHEN** приходит запрос только со старой кукой
- **THEN** ответ 401

### Requirement: Сравнение путей скоупа по платформе
Система SHALL определять вложенность и пересечение каталогов пользователей одной функцией с учётом платформы: на Windows — без учёта регистра и вида разделителя, на POSIX — с разделителем «/» и с учётом регистра. Удаление папки учётной записи SHALL отказывать, если папка совпадает с каталогом другого пользователя, содержит его или лежит внутри него.

#### Scenario: Вложенный каталог живого пользователя на Linux
- GIVEN платформа linux, удаляется пользователь A с папкой `/srv/tenants/a`, у пользователя B есть каталог `/srv/tenants/a/shared-b`
- WHEN система решает, можно ли удалить папку `/srv/tenants/a`
- THEN папка считается занятой и не удаляется

#### Scenario: Общий префикс имени — не вложенность
- GIVEN каталоги `/home/t/a` и `/home/t/ab`
- WHEN система сравнивает их
- THEN они не пересекаются

#### Scenario: Windows — поведение прежнее
- GIVEN платформа win32, каталоги `D:\T\A\inner` и `d:/t/a`
- WHEN система сравнивает их
- THEN первый лежит внутри второго

### Requirement: Плашка завершённой сессии

Система SHALL после ответа 401 посреди работы показывать на экране входа плашку «Сессия завершена. Войдите снова — если токен не подходит, попросите новый у администратора.», не утверждая, что токен недействителен: причина 401 (выход в другой вкладке, срок, перевыпуск токена, отключение) клиенту неизвестна. При первом входе плашки нет. (трекер: BUG-04.16)

#### Scenario: Выход в другой вкладке

- **GIVEN** пользователь работает в чате, а в другой вкладке той же куки нажал «Выйти»
- **WHEN** первая вкладка получает 401
- **THEN** открывается экран входа с плашкой «Сессия завершена. Войдите снова…», и вход тем же токеном проходит

#### Scenario: Первый визит

- **WHEN** пользователь впервые открывает портал без входа
- **THEN** плашки «Сессия завершена» нет
