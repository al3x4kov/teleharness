# observability Specification

## Purpose
Наблюдаемость портала: проверка здоровья zai-web для watchdog и выката (`/zai/api/healthz`) и журнал запросов edge и zai-web без секретов (ADR-007).

## Requirements

### Requirement: Проверка здоровья

Система SHALL отвечать на `GET /zai/api/healthz` без авторизации и только с 127.0.0.1 (ADR-007). При свежем индексе сессий и живом upstream ответ — 200 с ok, версией, эпохой и счётчиками; иначе — 503. Watchdog перезапускает zai-web после двух провалов подряд. (трекер: TASK-12.20)

#### Scenario: Upstream недоступен

- **WHEN** opencode upstream не отвечает дольше 60 с
- **THEN** healthz отвечает 503 с ok=false

#### Scenario: Внешний запрос

- **WHEN** healthz запрашивают снаружи через edge
- **THEN** ответ 404

### Requirement: Журнал запросов

Система SHALL писать access-лог edge и zai-web: одна JSON-строка на запрос (время, request-id, метод, путь без query, статус, длительность, пользователь, IP). Токены, cookie и тела не пишутся; ротация по дате и размеру, хранение 14 дней, выключение через ZAI_ACCESS_LOG=0. (трекер: TASK-12.20)

#### Scenario: Запрос к API

- **WHEN** клиент вызывает /zai/api/session
- **THEN** в журнале появляется строка со статусом и длительностью, без токена и cookie

### Requirement: Память и ошибки апстрима в healthz
Ответ healthz SHALL содержать память процесса сервера (`mem.rssMb`, `mem.heapUsedMb`), число ошибок обращения к движку за последние 5 минут (`errors.upstream5m`) и признак `degraded`, когда память превышает порог `ZAI_MEM_WARN_MB`.

#### Scenario: Память выше порога
- **GIVEN** порог `ZAI_MEM_WARN_MB` ниже текущей памяти процесса
- **WHEN** запрашивается healthz с loopback
- **THEN** ответ содержит `degraded: true` и значения памяти, код ответа определяется только доступностью движка

### Requirement: Оповещение после нечистого завершения
Сервер SHALL при старте определять, что предыдущий запуск завершился нечисто, писать это в лог и отправлять администратору push-уведомление, если у него есть подписка; время сбоя SHALL быть видно в healthz.

#### Scenario: Старт после сбоя
- **GIVEN** предыдущий запуск сервера был убит без остановки
- **WHEN** сервер стартует
- **THEN** в логе есть запись о нечистом завершении, healthz содержит `lastCrashAt`, администратору отправлен push

#### Scenario: Старт после обычной остановки
- **GIVEN** предыдущий запуск остановлен штатно
- **WHEN** сервер стартует
- **THEN** оповещение не отправляется и `lastCrashAt` отсутствует

### Requirement: Не-прод экземпляр не работает с прод-opencode
Экземпляр сервера с `ZAI_ENV`, отличным от `prod`, SHALL отказываться стартовать, если адрес движка указывает на любой прод-порт opencode (1.x или 2.x).

#### Scenario: Стенд с адресом прод-opencode 2.x
- **GIVEN** `ZAI_ENV=stand` и `ZAI_UPSTREAM=http://127.0.0.1:4196`
- **WHEN** сервер запускается
- **THEN** процесс завершается с кодом 1 и сообщением об отказе работать с прод-апстримом

### Requirement: Служебные запросы ограничены по времени и нагрузке
Запрос состояния MCP SHALL завершаться в пределах общего бюджета времени (130 секунд) даже при молчащем движке. Одновременные запросы статуса чатов с истёкшим кэшем SHALL вызывать один пересчёт. Кэш списка команд по папкам SHALL иметь потолок размера.

#### Scenario: Движок принял соединение и молчит
- GIVEN движок не отвечает на запрос состояния MCP
- WHEN пользователь открывает настройки MCP
- THEN ответ приходит не позже общего бюджета, а не после двух полных ожиданий

#### Scenario: Несколько вкладок одновременно
- GIVEN кэш статуса истёк
- WHEN два запроса статуса приходят одновременно
- THEN к движку уходит один запрос, оба клиента получают один результат
